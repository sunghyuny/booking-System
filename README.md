프로젝트 기획서: AI-Driven Hotel Booking System 
프로젝트명 대규모 트래픽 대비 숙박 예약 및 AI 기반 노쇼(No-Show) 예측 시스템 
프로젝트 개요목적: 특가 이벤트 시 발생하는 대규모 트래픽을 안정적으로 처리하고, 인메모리 캐시 및 비동기 메시지 큐를 활용하여 DB 병목을 해결합니다. 또한, AI 모델을 연동하여 예약 취소 확률을 예측함으로써 호텔 운영의 효율성을 높이는 실무형 백엔드 시스템 구축을 목표로 합니다.핵심 타겟: 대용량 데이터 처리, 동시성 제어, MSA(Microservices Architecture) 구조 설계 역량 증명.
시스템 아키텍처 (System Architecture)Spring Boot (Main): 유저 인증, 예약 트랜잭션 및 전반적인 비즈니스 로직 담당.FastAPI (AI Server): Python 기반 머신러닝 모델(취소 예측) 서빙 전담.Redis: 잔여 객실 조회 및 세션 데이터 캐싱을 통한 DB 부하 절감.RabbitMQ: 예약 완료 후 AI 분석을 위한 데이터를 비동기적으로 전달하여 병목 방지.MySQL: 관계형 데이터베이스를 통한 데이터 정합성 보장.
데이터베이스 설계 (ERD)주요 테이블 및 관계:Users (1) : Reservations (N)Hotels (1) : Rooms (N)Rooms (1) : Reservations (N)특이사항: Reservations 테이블에 ai_cancel_prob 컬럼을 배치하여 AI 예측 결과값을 관리자 대시보드에서 활용 가능하도록 설계.🔗 핵심 API 명세서 (API Specification)구분MethodURI설명기술적 포인트인증POST/api/v1/users/loginJWT 로그인토큰 기반 보안조회GET/api/v1/hotels/{id}/rooms잔여 객실 조회Redis 캐싱예약POST/api/v1/reservations객실 예약 생성Pessimistic Lock, RabbitMQAIPATCH/api/v1/internal/res/{id}/probAI 취소 확률 업데이트MSA 간 API 통신관리GET/api/v1/admin/reservations노쇼 위험도 대시보드비즈니스 가치 창출
주요 문제 해결 시나리오 (Troubleshooting Plan)조회 성능 최적화:문제: 수만 명의 동시 접속자가 객실 정보를 조회할 때 DB I/O 병목 발생.해결: Redis를 활용한 Look-aside 캐싱 패턴 적용으로 조회 성능 극대화.동시성 이슈 해결:문제: 마지막 남은 객실 하나를 동시에 두 명 이상이 예약하는 'Race Condition' 발생.해결: DB 수준의 비관적 락(Pessimistic Lock) 또는 Redis 기반의 분산 락을 검토하여 정합성 보장.서버 간 통신 및 블로킹 방지:문제: 무거운 AI 연산(취소 예측)이 메인 서버의 응답 속도를 저해함.해결: RabbitMQ를 활용한 비동기 메시징 구조로 설계하여 AI 연산과 관계없이 즉각적인 예약 완료 응답 반환.🛠 추후 진행 계획[ ] Spring Boot 프로젝트 초기 환경 설정 및 의존성 주입[ ] 도메인별 Entity 개발 및 MySQL 연동[ ] Redis 및 RabbitMQ 인프라 구축 (Docker 활용)[ ] FastAPI 기반 AI 모델 서빙 API 구현[ ] 부하 테스트 툴(k6 등)을 활용한 성능 검증 및 최적화
